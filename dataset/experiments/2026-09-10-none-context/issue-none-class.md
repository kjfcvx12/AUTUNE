분류기는 **"해당 없음" 이라고 답할 수 없습니다.** AMI 발화의 84.8% 가 다섯 클래스 밖인데, 학습·평가·추론 모두 다섯 클래스만 압니다. 그래서 회의의 모든 발화가 다섯 중 하나로 나옵니다 — 그리고 지금 지표는 그걸 볼 수 없습니다.

GPU 로 전체 AMI 를 학습해 **실제 회의 분포**(해당 없음 포함)에서 재봤습니다:

| | 라벨 있는 발화만 (#115 방식) | **실제 회의 분포** |
| --- | --- | --- |
| 5-way macro F1 | 0.655 | **0.225** |
| 발화 2,400 개(45분 회의)당 거짓 라벨 | — | **1,888 개** |
| 예측된 `decision` 중 진짜 | 62% | **12%** |

`none` 클래스를 추가하면 거짓 라벨이 **절반**(953 개)으로 줄고, 라벨 있는 발화 성능은 거의 그대로입니다 (0.650). 필요하지만 그것만으로는 부족합니다. 앞뒤 문맥을 붙이는 것은 `decision` 에만 효과가 있었습니다.

## 1. 어디서 빠지는가

`AmiReader.acts()` 전체를 `ami.label_for` 에 통과시켰습니다.

```
acts 117,915   labelled 17,876 (15.2%)   unlabelled 100,039 (84.8%)

  Inform 25.5% · Assess 14.6% · Fragment 14.2% · Backchannel 10.7%
  Stall 7.2% · Suggest 7.1% · Be-Positive 1.9% · Other 1.9% · …
```

| 단계 | 지금 | "해당 없음" 발화는 |
| --- | --- | --- |
| 매핑 `labeling/ami.py` `label_for` | 다섯 중 하나, 또는 `None` | `None` — 의도된 동작입니다 |
| 로더 `labeling/corpus.py` `AmiReader.load` | `None` 이면 버림 | **학습셋에 없음** |
| 학습 `training/dataset.py` `LABELS` | 5-way head | 한 번도 못 봄 |
| 평가 `eval/` · #115 | 라벨 있는 발화만 채점 | **평가셋에 없음 — 지표가 이 문제를 볼 수 없음** |
| 추론 `pipeline/classifier.py` (#97) | 5-way softmax, 합 1 | **반드시 다섯 중 하나** |

로더 docstring 이 이미 절반을 말하고 있습니다: *"a loader that forced a label on them would teach the model that everything is a commitment."* 학습에서는 맞게 피했는데, **추론에서는 그 발화들이 전부 들어옵니다.**

## 2. 실험

kf-deberta-base, 전체 AMI, RTX 3060, 3 epoch, 역빈도 class weight, seed 1 개. 네 조합입니다.

- **5-way / 6-way** — 6-way 는 `none` 을 라벨 있는 발화와 **1:1** 로 샘플링해 추가
- **문맥 0 / 2** — 문맥 2 는 앞 2 발화 + 뒤 2 발화를 시간순으로, 같은 화자인지 표시해 붙임. 대상 발화는 두 조건 모두 94 토큰까지

평가는 두 가지입니다.

- **닫힌 평가** — 테스트 회의의 라벨 있는 발화 2,060 개. #115 와 같은 조건
- **실제 분포** — 결정 주석이 있는 테스트 회의 7 개의 **모든** 발화 5,237 개 (해당 없음 4,119 = 78.7%). 결정 주석은 47 개 회의에만 있어서, 나머지 회의의 "해당 없음" 에는 주석 안 된 결정이 섞여 있을 수 있습니다. 그래서 7 개로 제한했습니다

### 임계값(#122)으로 거를 수 있나 — 없습니다

신뢰도 기준 이상으로 남는 비율 (라벨 있는 발화 / 해당 없음 발화):

| 기준 | 문맥 0 · 5-way | 문맥 0 · 6-way (1 − P(none)) |
| --- | --- | --- |
| 0.5 | 86% / 76% | 93% / 61% |
| 0.7 | 60% / 43% | 79% / 39% |
| 0.9 | 34% / **8%** | 52% / 11% |

5-way 에서 0.9 로 올려도 **해당 없음이 라벨 있는 발화보다 3.7 배 많아서** 남는 것 중 절반 가까이가 여전히 거짓이고, 재현율은 34% 로 떨어집니다. ADR 0006 은 재현율을 정밀도 위에 둡니다. 게다가 이 기준은 "해당 없음" 이 들어간 평가셋이 있어야 정할 수 있는 숫자입니다.

## 3. 읽은 것

**`none` 은 필요합니다.** 거짓 라벨이 절반이 되고, 신뢰도 분리도(AUROC)가 0.64 → 0.80 이 되고, 닫힌 평가는 0.005 만 잃습니다. 계약도 안 건드립니다 — `none` 은 B 안에서 걸러지면 되고, `ExtractionResult.classifications` 는 지금도 모든 발화를 담는다고 정의돼 있지 않습니다.

**그런데 `none` 만으로는 부족합니다.** 6-way 도 해당 없음의 절반(49.5%)만 `none` 으로 보냅니다. 1:1 로 샘플링했는데 실제는 3.7:1 이라, 모델이 `none` 을 실제보다 드물다고 배웠을 가능성이 큽니다 — 비율을 올려서 다시 재야 합니다.

**문맥은 `decision` 에만 효과가 있었습니다.** 제 가설은 "라벨이 문맥으로 정해지는 클래스(구간 근거 `decision`, 관계 근거 `concern` · `ambiguous`)가 문맥으로 좋아진다" 였습니다. 결과는 반만 맞았습니다.

- `decision` (구간 근거): **0.605 → 0.670.** 가장 큰 개선입니다
- `concern` (관계 근거): 0.623 → 0.642. 작습니다
- `ambiguous` (관계 근거): 0.434 → **0.401. 오히려 떨어졌습니다**
- 6-way 에서는 문맥이 실제 분포 점수를 올리지 못했습니다 (0.325 → 0.306)

관계 근거 라벨이 좋아지지 않은 이유는 아직 모릅니다. 가능성은 둘입니다: AMI 의 adjacency pair 는 source 가 바로 앞 발화가 아닐 수 있고(시작 시각 정렬은 겹치는 발화를 섞음), 제 문맥 형식이 단순했습니다. 또는 그 라벨 자체가 텍스트로 배우기 어려운 주석일 수 있습니다. **실제 source 발화를 붙이는 실험(상한선)** 이 둘을 가릅니다.

**`decision` 은 발화 단위 분류가 맞지 않을 수 있습니다.** 라벨이 "결정 구간 안의 assertive 발화" 라서 같은 Inform 이 구간 안이면 `decision`, 밖이면 `None` 입니다. 앞뒤 2 발화로는 구간 경계를 볼 수 없습니다. #99 가 이미 결정을 발화 묶음(엔티티)으로 만들고 있으니, 구간 검출로 옮기는 것이 검토할 만합니다.

**#115 의 점수는 데이터 부족이 컸습니다.** #115 는 학습 데이터 4,000 개, 2 epoch, 임베딩 고정(`freeze_embeddings`) 실행이었습니다. 전체 데이터에서 `ambiguous` 는 0.270 → 0.434, 닫힌 macro F1 은 0.608 → 0.655 입니다.

**잡음 크기:** 문맥 0 · 6-way 를 seed 3 개로 반복했습니다. 닫힌 평가 0.648 ± 0.003, 실제 분포 0.314 ± 0.010, 거짓 라벨 990 ± 33. 닫힌 평가의 문맥 효과(+0.02)는 실제 효과이고, 6-way 에서 문맥이 실제 분포 점수를 바꾸지 못한 것도 잡음 범위 안입니다.

**데이터 양:** 학습 회의 12.5% → 25% → 50% → 100% 에서 닫힌 평가는 0.539 → 0.582 → 0.622 → 0.648 로 계속 오릅니다 (`ambiguous` 가 가장 가파름). 그런데 `decision` 은 0.50–0.57 에서 평평하고, 해당 없음이 `decision` 으로 가는 수도 1,100 개 안팎에서 줄지 않습니다. **데이터를 늘려도 `decision` 과 거짓 라벨은 해결되지 않습니다.**

**한계:** 실제 분포 평가는 회의 7 개입니다. AMI 는 영어고 제품은 한국어입니다. adjacency pair 주석이 빠진 발화가 "해당 없음" 에 섞여 있으면 실제 분포 점수는 비관적으로 나옵니다.

## 4. 제안

1. **`none` 클래스를 넣습니다** (모듈 B 내부). 로더가 `None` 발화를 `none` 으로 쓰고, 분류기는 `none` 을 결과에서 뺍니다. 계약 변경 없음.
2. **평가셋에 "해당 없음" 을 실제 비율로 넣고, 지표를 그 위에서 잽니다.** 이게 없으면 지표가 이 문제를 못 봅니다. #10 의 평가셋, #122 의 임계값 모두 이 분포에서 정해야 합니다.
3. **ADR 0006 지표를 고칩니다:** "five-way macro F1" → "해당 없음이 실제 비율로 섞인 평가셋에서, 다섯 클래스에 대한 macro F1". `none` 은 평균에 넣지 않습니다 (쉬운 다수 클래스가 점수를 끌어올림). 해당 없음을 어떤 kind 로 잘못 보내면 그 kind 의 정밀도에서 잡힙니다.
4. **한국어 LLM 1차 라벨링(#10)의 프롬프트가 "해당 없음" 을 답할 수 있어야 합니다.** 다섯 중에서 고르게 하면 같은 구멍이 한국어 데이터에서 다시 생깁니다.
5. **문맥은 아직 채택하지 않습니다.** 아래 실험 결과를 보고 정합니다.

### 한국어 평가셋

그대로 쓸 수 있는 한국어 데이터는 없습니다. 화행 라벨이 있는 AI Hub 셋(#544 용도별 목적대화, #543 주제별 일상대화)은 콜센터·메신저 2인 대화이고 `decision` · `concern` · `ambiguous` 에 해당하는 라벨이 없습니다. 국립국어원 말뭉치에는 화행 층이 없고, 한국어 액션 아이템·결정 벤치마크는 없습니다.

그래서 만듭니다. **AI Hub 회의 음성인식(#464) 으로 먼저, 팀 자체 회의로 보강** (ADR 0006 의 본 평가셋).

1. **파일럿:** 서울시의회 상임위 질의응답 2 회의, 747 행을 두 사람이 **독립적으로** 라벨링해 일치도(κ)를 잽니다. 이 κ 가 우리 지표의 상한입니다. 라벨링 가이드 초안과 일치도 스크립트는 준비돼 있습니다.
2. 파일럿 κ 와 클래스 비율을 보고 전체 규모를 정합니다.
3. **AI Hub 약관:** 제3자 제공 금지, 해외 이전은 NIA 별도 협약. LLM 1차 라벨링을 해외 API 로 하면 걸릴 수 있습니다 — 로컬 모델로 하거나 확인이 필요합니다.
4. AI Hub 회의 발화는 억양 단위로 잘려서 문장이 두 행에 걸칩니다. 모듈 A 가 내는 발화 단위와 같은지 확인해야 하고, 가이드는 "문장이 끝나는 행에 라벨" 로 정했습니다.
