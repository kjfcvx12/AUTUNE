## 1. `review.html` cursor fix

- **Bug:** when a filter was on, the cursor still started on row 0, which the
  filter hides. `Enter` did nothing until `J` moved onto a visible row.
- **Fix:** a new `firstVisible()` in
  `dataset/extraction_eval_pilot/review.html`.
  - Switching meetings (`]` / `[` too) and changing the order start on the first
    row the filter shows.
  - Changing the filter moves the cursor only when the current row becomes
    hidden.
  - A filter that shows nothing falls back to the first row.
- **Test:** a headless-Chrome harness with invented rows (session scratchpad,
  `mk_harness.py`). 12 checks × 3 runs pass. The same harness fails on the
  pre-fix code.
- **Gotcha:** a harness script must not declare a top-level `const` that
  review.html already declares (`key`, `rows`, `state`, `$`). The redeclaration
  is a parse error, so the harness never runs and prints nothing.

## 3. Prompt refinement (`refine.py`)

  commitments).
- **Prompts compared:**

  - v1: the six-way prompt with "a concrete action after this meeting", plus
    invented examples of "~겠습니다" forms that are not commitments
  - yn: a yes/no question
- **Commands:** `python refine.py score` (GPU, conda env `aiprj`, batch 6,
  1.6–2.3 rows/s) and `python refine.py report`. Scores are saved in
  `results/refine_scores.json`.

**Findings**

- **Rerun noise:** the rerun p differs from the scan's by 0.036 on average
  (max 0.32). Candidate status flips on 3 rows.
- **Why commitments are missed:** of the 56 neighbour commitments, 6 fail the
  ending pre-filter and **50 pass it but get p < 0.10**. Recall is limited by the
  model, not by the filter or `--pmin`.
